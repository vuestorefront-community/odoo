# 🔐 Authentication System

The boilerplate implements a comprehensive authentication system using ODOO sessions, HTTP-only cookies, and route protection middleware.

### 🍪 Session Management

#### Session ID Cookie

The system uses ODOO's native session management through `session_id` cookies:

```typescript
// server/api/odoo/query.post.ts
export default defineEventHandler(async (event: H3Event) => {
  const config = useRuntimeConfig(event)
  const body = await readBody(event)
  
  // Automatically include session_id in requests to ODOO
  const response = await $fetch.raw(`${config.public.odooBaseUrl}graphql/vsf`, {
    method: 'POST',
    headers: {
      'accept': 'application/json',
      'content-type': 'application/json',
      'REAL-IP': getRequestIP(event) || '',
      'Cookie': `session_id=${getCookie(event, 'session_id')}`,
    },
    body: JSON.stringify({ query: Queries[body?.[0]?.queryName], variables: body?.[1] }),
  })

  return response?._data?.data
})
```

#### User Data Cookie

In addition to the session cookie, user data is cached in a separate cookie:

```typescript
// layers/auth/composables/useAuth.ts
export const useAuth = () => {
  // User data cached in cookie for quick access
  const userCookie = useCookie<any | null>('odoo-user', { 
    maxAge: 3600 * 30,  // 30 hours
    httpOnly: false,    // Accessible from client-side
    secure: true,       // Only sent over HTTPS
    sameSite: 'strict'  // CSRF protection
  })
  
  // User data in reactive state
  const user = useState<Partner>('user', () => ({}) as Partner)

  const login = async (params: MutationLoginArgs) => {
    try {
      loading.value = true
      const data = await $sdk().odoo.mutation<MutationLoginArgs, SignInUserResponse>(
        { mutationName: MutationName.LoginMutation }, 
        { ...params }
      )

      // Store user ID in cookie and full user data in state
      userCookie.value = data?.login?.user?.partner
      user.value = data?.login?.user?.partner as Partner
      
      router.push('/my-account/personal-data')
    }
    finally {
      loading.value = false
    }
  }
}
```

### 🛡️ Route Protection

#### Authentication Middleware

The system uses Nuxt route middleware to protect authenticated routes:

```typescript
// middleware/auth-check.ts
export default defineNuxtRouteMiddleware((to, from) => {
  const { isAuthenticated } = useAuth()
  if (!isAuthenticated.value) {
    return '/login'
  }
})
```

#### Authentication State

The authentication state is computed from both cookie and user data:

```typescript
// layers/auth/composables/useAuth.ts
const isAuthenticated = computed(() => {
  return user?.value?.id || Boolean(userCookie.value)
})
```

#### Protected Routes Usage

Apply the middleware to pages that require authentication:

```vue
<!-- pages/my-account/personal-data.vue -->
<template>
  <div>
    <!-- Protected content -->
  </div>
</template>

<script setup lang="ts">
// This page requires authentication
definePageMeta({
  middleware: 'auth-check'
})
</script>
```

### 🔄 Session Lifecycle

#### User Login Process

1. **Credentials Submission**: User submits login form
2. **ODOO Authentication**: Backend validates credentials with ODOO
3. **Session Creation**: ODOO creates session and returns `session_id`
4. **Cookie Setting**: Session cookie is automatically set by browser
5. **User Data Storage**: User data cached in `odoo-user` cookie
6. **State Update**: Reactive user state updated
7. **Route Redirect**: User redirected to protected area

```typescript
const login = async (params: MutationLoginArgs) => {
  try {
    loading.value = true
    
    // Authenticate with ODOO
    const data = await $sdk().odoo.mutation<MutationLoginArgs, SignInUserResponse>(
      { mutationName: MutationName.LoginMutation }, 
      { ...params }
    )

    // Update local state
    userCookie.value = data?.login?.user?.partner
    user.value = data?.login?.user?.partner as Partner
    
    // Redirect to protected area
    router.push('/my-account/personal-data')
  }
  finally {
    loading.value = false
  }
}
```

#### User Logout Process

1. **Logout Request**: User clicks logout
2. **ODOO Logout**: Backend invalidates session with ODOO
3. **Cookie Clearing**: Local cookies are cleared
4. **State Reset**: User state reset to empty
5. **Route Redirect**: User redirected to public area

```typescript
const logout = async () => {
  // Clear local state
  userCookie.value = null
  user.value = {} as Partner
  
  // Invalidate session with ODOO
  await $sdk().odoo.mutation<null, null>({
    mutationName: MutationName.LogoutMutation,
  })
  
  // User will be redirected by auth middleware
}
```

### 🔐 Security Features

#### Cookie Security

```typescript
// Secure cookie configuration
const userCookie = useCookie<any | null>('odoo-user', {
  maxAge: 3600 * 30,      // 30 hours expiration
  httpOnly: false,        // Accessible from client (for UI state)
  secure: true,           // Only sent over HTTPS in production
  sameSite: 'strict',     // CSRF protection
  encode: value => btoa(JSON.stringify(value)), // Base64 encoding
  decode: value => JSON.parse(atob(value)),     // Base64 decoding
})
```

#### Request Security

All API requests automatically include authentication headers:

```typescript
// Automatic session inclusion
headers: {
  'REAL-IP': getRequestIP(event) || '',
  'resquest-host': config.public.middlewareUrl || getRequestHost(event),
  'Cookie': `session_id=${getCookie(event, 'session_id')}`,
}
```

### 🔄 Session Persistence

#### Cart Session Integration

The cart system uses the same session for persistence:

```typescript
// server/api/odoo/cart-load.get.ts
export default defineEventHandler(async (event: any) => {
  const session = await useSession(event, {
    password: 'b013b03ac2231e0b448e9a22ba488dcf',
  })
  
  // Cart is tied to user session
  const keyName = `cache:cart:${session?.id}`
  const data = await useStorage('cart').getItem(keyName)
  
  return data || {}
})
```

#### Cross-Request Persistence

Session data persists across requests through cookies:

```typescript
// User state loads from cookie on app initialization
const loadUser = async (withoutCache: boolean = false) => {
  loading.value = true

  const query = withoutCache ? $sdk().odoo.queryNoCache : $sdk().odoo.query

  const data = await query<null, LoadUserQueryResponse>({
    queryName: QueryName.LoadUserQuery,
  })

  // Update both cookie and state
  userCookie.value = data?.partner?.id
  user.value = data?.partner

  loading.value = false
}
```

### 🎯 Best Practices

1. **Dual Storage**: Session ID in HTTP-only cookie, user data in accessible cookie
2. **State Synchronization**: Keep cookie and reactive state in sync
3. **Security Headers**: Include IP and host information in requests
4. **Automatic Cleanup**: Clear all auth data on logout
5. **Route Protection**: Use middleware for consistent protection
6. **Session Validation**: Validate session on protected API calls
