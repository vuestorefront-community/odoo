# 📖 Usage Examples

The system provides two different approaches for making API requests, depending on the context:

### 🔄 Page Load Requests - Using `useAsyncData`

When data needs to be fetched during page load or reload, use Nuxt's `useAsyncData` for SSR support and optimal performance.

```typescript
// Example: Loading product data on page load
const loadProductTemplate = async (params: QueryProductArgs) => {
  if (productTemplate?.value?.id) {
    return
  }
  
  const { data, error, status } = await useAsyncData(`product-${cleanSlug}`, () =>
    $sdk().odoo.query<QueryProductArgs, ProductResponse>(
      { queryName: QueryName.GetProductTemplateQuery },
      params,
      { headers: useRequestHeaders() },
    ),
    { lazy: import.meta.client },
  )

  if (import.meta.server) {
    productTemplate.value = (data?.value?.product as CustomProductWithStockFromRedis) || {}
    if (!productTemplate.value?.id) {
      showError({
        status: 404,
        message: 'Product not found',
      })
    }
  }

  watch(status, () => {
    if (status.value === 'error' && !data?.value) {
      showError({
        status: 404,
        message: 'Product not found',
      })
    }

    if (status.value === 'pending') {
      loadingProductTemplate.value = true
    }
    if (status.value === 'success') {
      loadingProductTemplate.value = false
      productTemplate.value = (data?.value?.product as CustomProductWithStockFromRedis) || {}
    }
  })
}
```

**Key Features:**
- ✅ SSR support with server-side data fetching
- ✅ Automatic loading states management
- ✅ Error handling with `showError()`
- ✅ Unique cache keys for each request
- ✅ Lazy loading on client-side

### 👆 User Interaction Requests - Using `$sdk`

For requests triggered by user actions (clicks, form submissions, etc.), use the `$sdk` directly.

```typescript
// Example: User logout action
const logout = async () => {
  userCookie.value = null
  user.value = {} as Partner
  await $sdk().odoo.mutation<null, null>({
    mutationName: MutationName.LogoutMutation,
  })
}

// Example: User login action
const login = async (params: MutationLoginArgs) => {
  try {
    loading.value = true
    const data = await $sdk().odoo.mutation<
      MutationLoginArgs,
      SignInUserResponse
    >({ mutationName: MutationName.LoginMutation }, { ...params })

    userCookie.value = data?.login?.user?.partner
    user.value = data?.login?.user?.partner as Partner
    router.push('/my-account/personal-data')
  }
  finally {
    loading.value = false
  }
}

// Example: Fetching orders on user action
const getOrders = async () => {
  loading.value = true
  const data = await $sdk().odoo.query<null, GetOrdersResponse>(
    { queryName: QueryName.GetOrdersQuery },
    null,
  )
  loading.value = false
  orders.value = (data?.orders as Orders) || {}
}
```

**Key Features:**
- ✅ Direct API calls without SSR overhead
- ✅ Manual loading state management
- ✅ Immediate response handling
- ✅ Perfect for user-triggered actions

### 📋 When to Use Each Approach

| Context | Method | Use Case |
|---------|--------|----------|
| **Page Load** | `useAsyncData` | Product pages, category pages, initial data |
| **User Interaction** | `$sdk` | Login, logout, add to cart, form submissions |
| **Navigation** | `useAsyncData` | Route changes, page refreshes |
| **Button Clicks** | `$sdk` | Any action triggered by user input |

### 🎯 Best Practices

1. **Always use `useAsyncData` for page-level data** that needs to be available on first load
2. **Use `$sdk` for interactive features** like buttons, forms, and user actions
3. **Include proper error handling** for both approaches
4. **Manage loading states** appropriately for better UX
5. **Use unique cache keys** in `useAsyncData` to avoid conflicts

This pattern ensures optimal performance, proper SSR behavior, and excellent user experience across your application.
