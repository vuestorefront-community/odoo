# 📡 Server API Layer

The server layer acts as a bridge between the frontend and the ODOO GraphQL API, providing three main endpoints with different caching strategies.

## 🔍 Main Endpoints

### 1. **POST `/api/odoo/query`** - Queries with Cache
Optimized endpoint with SWR cache for data that doesn't change frequently.

**When to use:**
- 📦 Product data
- 🏷️ Categories
- 📄 Static content

### 2. **POST `/api/odoo/query-no-cache`** - Queries without Cache
Endpoint for data that needs to be always up-to-date.

**When to use:**
- 👤 User data
- 🛒 Shopping cart
- 📊 Real-time inventory

### 3. **POST `/api/odoo/mutation`** - GraphQL Mutations
Endpoint for data modification operations.

**When to use:**
- 🛒 Add/remove cart items
- 👤 Login/logout
- 📍 Manage addresses

## 💡 Practical Example: Cache Control

```typescript
// Example usage with cache control
const loadUser = async (withoutCache: boolean = false) => {
  loading.value = true

  // Choose endpoint based on cache needs
  const query = withoutCache ? $sdk().odoo.queryNoCache : $sdk().odoo.query

  const data = await query<null, LoadUserQueryResponse>({
    queryName: QueryName.LoadUserQuery,
  })

  userCookie.value = data?.partner?.id
  user.value = data?.partner
  loading.value = false
}

// Usage:
await loadUser(false)  // With cache - data may come from cache
await loadUser(true)   // Without cache - always fetch fresh data
